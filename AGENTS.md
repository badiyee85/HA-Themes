# AGENTS.md — HA Themes (theme pack for Hermes Desktop)

## Status
- v0.3.0: two themes, `winforms` (WinForms) and `badi-dark-desktop` (Badi Dark (Desktop)).
- Public repository `badiyee85/HA-Themes`. Users install it by placing a tagged `desktop/plugin.js` at
  `<HERMES_HOME>/desktop-plugins/ha-themes/plugin.js` (README).
- Owner decisions and release records live outside this repo (the owner's task board). Keep this repo
  free of machine names, internal hosts, task ids and private paths (`test_nothing_private_in_tracked_files`).

## Purpose
Hand-made Hermes Desktop themes, shipped as one add-on that lists them in Settings → Appearance.

## Source of truth
- Edit `themes/<name>/theme.json` (DesktopTheme data; `name` = folder name) and the optional
  `themes/<name>/theme.css` (that theme's customCSS).
- `desktop/plugin.js` is GENERATED by `tools/build.py`; never hand-edit it.
- Docs authority: the live Hermes docs (developer-guide/desktop-plugin-sdk, user-guide/features/skins,
  plugin catalog + submission rules). `CONFORMANCE.md` maps each rule to evidence; update it with any change.

## Rules
- Themes, not skins. A theme's name must never equal a Desktop built-in, a CLI built-in skin or an
  installed user skin, because skins shadow themes on Desktop.
- CSS hooks are `data-*`, `role` and `aria-label` only, never class names. Every selector starts with
  `:root[data-hermes-theme='<theme>']`.
- Plugin JS stays data + one `ctx.registerMany(THEMES_AREA)`: no DOM, no `<style>`, no other imports.
- `main` only receives commits that passed every check below. Every release is tagged `vX.Y.Z` and bumps
  `plugin.yaml` (SemVer, 0.x). A version installed anywhere is spent: further changes bump again.
- `requires_hermes` is the oldest release where the hook check passes (`HERMES_SRC=<that tag>`).
- Only document install routes that a real-app test has passed. `hermes plugins install` is not one yet
  (on 0.22.5 the package's Desktop half did not appear in the app).

## Verification (all must pass before pushing)
1. `python3 tools/build.py`
2. `python3 tools/test_theme.py`, using a Python that imports `hermes_cli`. Repeat with
   `HERMES_SRC=<checkout>` for the floor release and for each Hermes build in use.
3. `hermes plugins validate .` (and against upstream `main` for forward compatibility).
4. `tools/shoot.sh <label>`: 2 real-app tests that install the built file into an isolated Desktop under Xvfb.
5. Visual side-by-side for WinForms: `tools/compare.py <label> 2-chat`. Curated copies go to `docs/shots/`.
